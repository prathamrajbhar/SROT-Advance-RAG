## 2. BYOK Cryptographic Vault (AES-256-GCM)

All customer-supplied API keys (OpenAI, Gemini, Anthropic, Groq) or private endpoint bearer tokens are encrypted before being written to disk.

### 2.1 Encryption Scheme & Envelope Design
- **Algorithm:** AES-256-GCM (Galois/Counter Mode) via `cryptography` (v50.0.1).
- **Master Key:** A 256-bit high-entropy secret (`ENCRYPTION_MASTER_KEY`) managed via environment variables or AWS KMS.
- **Nonce/IV:** 96-bit cryptographically secure pseudorandom number generated per encryption operation (`os.urandom(12)`).
- **Authentication Tag:** 128-bit tag generated by GCM ensuring ciphertext integrity and tampering detection.
- **Serialized Payload:** `base64(nonce [12 bytes] + ciphertext + auth_tag [16 bytes])`.

```python
# Technical implementation reference: apps/api/core/crypto.py
import os
import base64
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

class SecretVault:
    def __init__(self, master_key_bytes: bytes):
        if len(master_key_bytes) != 32:
            raise ValueError("Master encryption key must be exactly 32 bytes (256 bits).")
        self.aesgcm = AESGCM(master_key_bytes)

    def encrypt_secret(self, plaintext: str) -> str:
        nonce = os.urandom(12)
        ciphertext = self.aesgcm.encrypt(nonce, plaintext.encode("utf-8"), None)
        return base64.b64encode(nonce + ciphertext).decode("utf-8")

    def decrypt_secret(self, encrypted_payload: str) -> str:
        raw_bytes = base64.b64decode(encrypted_payload.encode("utf-8"))
        nonce = raw_bytes[:12]
        ciphertext = raw_bytes[12:]
        return self.aesgcm.decrypt(nonce, ciphertext, None).decode("utf-8")

    def mask_secret(self, plaintext: str) -> str:
        if len(plaintext) <= 8:
            return "••••••••"
        return f"••••••••{plaintext[-4:]}"
```

## 3. Tri-Layer Multi-Tenant Isolation

### 3.1 Layer 1: Relational Database (PostgreSQL 16)
- Every query executes with strict tenant predicates:
  ```sql
  SELECT * FROM documents WHERE tenant_id = :tenant_id AND workspace_id = :workspace_id;
  ```
- Fast composite B-tree indices on `(tenant_id, workspace_id)` guarantee query isolation and sub-millisecond lookups.

### 3.2 Layer 2: Object Storage (AWS S3)
- Prefix partitioning:
  `s3://{BUCKET}/{tenant_id}/{workspace_id}/{document_id}/...`
- The application generates presigned URLs constrained strictly to the requesting tenant's path prefix. No tenant can ever access or overwrite another tenant's object keys.

### 3.3 Layer 3: Vector Database (Qdrant v1.19.1)
- Every vector point stored in Qdrant has indexed payload keys: `tenant_id` and `workspace_id`.
- Every search query programmatically injects mandatory filter clauses:
  ```python
  query_filter = Filter(
      must=[
          FieldCondition(key="tenant_id", match=MatchValue(value=str(current_tenant.id))),
          FieldCondition(key="workspace_id", match=MatchValue(value=str(current_workspace.id)))
      ]
  )
  ```
- Cross-tenant vector leakage is mathematically impossible because points matching non-tenant filters are pruned before distance calculations.

## 4. Secure S3 Storage & Multipart Presigned Policy (Item 2)

Direct client-to-S3 uploads avoid buffer overflow and DoS attacks on the FastAPI gateway:
1. **Multipart Presigned Upload Policies:**
   - **Upload ID Verification:** The `s3_upload_id` is registered in PostgreSQL with the document owner (`tenant_id`, `workspace_id`). Any request to presign parts or complete uploads must authenticate the tenant's ownership.
   - **Part Size Bounds:** S3 presigned part URLs enforce part size boundaries (e.g. 5MB minimum, 10MB default) to prevent fragmented chunk floods.
   - **TTL:** Part presigned URLs expire strictly after **900 seconds (15 minutes)**.
   - **ETag Validation:** During `CompleteMultipartUpload`, the backend validates that all client-supplied ETags match S3 part verification headers before enqueuing Celery workers.
2. **Presigned Media Streaming (GET) Restrictions:**
   - Generated dynamically on user demand with 15-minute TTL.
   - Supports HTTP Range headers for fast seeking in audio/video players without exposing public bucket access.

## 5. Real-Time SSE Channel Authorization (Item 6)

- The Server-Sent Events endpoint `GET /api/v1/documents/:id/progress-stream` authenticates the user via JWT bearer token before initiating the Redis pub/sub listener.
- It queries PostgreSQL to confirm `document.tenant_id == current_user.tenant_id`.
- If unauthorized, it immediately terminates with HTTP 403 Forbidden, preventing malicious tenants from snooping on another tenant's processing progress.

## 6. Safe DuckDB SQL Execution Sandbox

Generating SQL from natural language against user-uploaded spreadsheets presents a potential injection risk if not strictly sandboxed.

### 6.1 Sandboxing Defenses
1. **Read-Only Mode:** DuckDB is invoked with `read_only=True` over in-memory or detached Parquet files.
2. **AST Statement Whitelisting:**
   - Every generated SQL statement is parsed before execution.
   - Only `SELECT` statements are permitted.
   - Keywords `PRAGMA`, `ATTACH`, `DETACH`, `COPY`, `INSTALL`, `LOAD`, `DROP`, `ALTER`, `CREATE`, `INSERT`, `UPDATE`, `DELETE` are rejected immediately.
3. **Execution Timeout:** Strict statement execution timeout capped at **5000ms** to prevent compute exhaustion attacks (e.g., recursive cross joins).

## 7. Audit Logging & Compliance (SOC2 / GDPR)

- **Audit Trail:** Every query, file upload, key rotation, and document deletion is logged in `query_sessions` and system audit tables with timestamp, user ID, IP address, and execution latency.
- **Right to Erasure (GDPR):** Deleting a document triggers an atomic cascade:
  1. Record deleted from PostgreSQL.
  2. S3 prefix deleted via S3 batch delete API.
  3. Qdrant vectors pruned via `delete_points(Filter(document_id=...))`.
